# Surge Rules Extension Plan

> Execute inline with the existing test-first and final-review workflow. User authorized adding Surge to the deployed project; prior upload authorization persists.

Goal: publish all upstream categories as native Surge RULE-SET files daily alongside existing QuanX outputs.

Architecture: retain the existing package and rule paths. A shared format specification controls rule names, policy fields, validation, metadata, index links and examples. A single workflow resolves/downloads one snapshot, builds both outputs, validates both before publishing, and writes separate quanx/surge branches. Existing QuanX Raw addresses stay stable.

## Decisions and alternatives

- Add a Surge format to the existing conversion/build pipeline (chosen by implementer); avoids duplicating eightythousand-category scanning, validation and report logic.
- Separate repository/workflow was considered but would duplicate synchronization and allow different source snapshots; not appropriate to this small extension.
- Native two-field Surge entries: DOMAIN, DOMAIN-SUFFIX, DOMAIN-KEYWORD, DOMAIN-WILDCARD, IP-CIDR, IP-CIDR6. Bind the policy on the caller's RULE-SET line; do not force no-resolve.
- Keep unsupported domain_regex in per-format reports; never approximate using URL-REGEX.
- Output branch and format must agree. Legacy summaries without a format field mean quanx.
- Do not change the installed Surge app or the user's live profile. Use surge-cli --check on generated temporary validation profiles.

## Review focus

- QuanX output must retain existing rule text, Raw URLs and default CLI behavior.
- Surge output must omit policy fields, use IP-CIDR6 and keep leading-dot suffix matching exact.
- Build both formats from the same SHA and download; no partial successful build may start publication.
- Wrong-format branch publication must fail before changing a remote branch.
- Reports, indexes and README must identify and link to their own format, including future classifications.
